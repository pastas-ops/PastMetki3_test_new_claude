# Записка для Claude (читать первой в новом чате, чтобы не тратить лимиты)

Проект PastMetki: один файл `www/index.html` (HTML+CSS+JS-модуль, Firebase Auth/Firestore), Android через Capacitor + нативные виджеты (`native/`),
сборка в GitHub Actions (`.github/workflows/build.yml`). Пользователь пишет по-русски, не программист: давать короткие понятные шаги.
Версия сейчас **1.1.0** (package.json - единственный источник версии; в index.html константа VER, ещё www/version.json, sw.js кэш pm-110).
Название APK: `pastmetki-ВЕРСИЯ.apk` (делает workflow). APK здесь собрать нельзя (нет Android SDK и сети): собирает GitHub.

## Что сделано в части 1 (всё проверено тестами `tests/t_main.js`, 60 проверок)
- Даты у пунктов плана: поле `dd` ('YYYY-MM-DD') рядом с `tm` у task `{text,done,tm,dd}` (и у пунктов сообщений `k[]`). ITEMS() собирает
  датированные пункты (мои заметки + shared). Показ: календарь (icard, кнопка `ilink` «К плану»), главная (irow в Сегодня/Просрочено/Предстоящие),
  PCT (прогресс), schedN (уведомления), pushW (виджет дедлайнов). Shared-документ создаётся, если есть due ИЛИ датированный пункт (hasD()).
- Вложения: `note.at` / `msg.at` = мета `{id,k:'p'|'d'|'l',n,t,s,th,u}`; сами файлы в Firestore `files/{id}` `{o,m,n,t,s,d(dataURL),ts}`;
  до 640 КБ, фото сжимаются (1280px). Отложенная загрузка: до сохранения данные в памяти FD{}. ATZ/ATV/ATI - разметка, addFiles/attWrite/rmFiles/openAtt/saveAtt.
  Нативный метод плагина `saveFile` (MediaStore Downloads/PastMetki). В редактировании СООБЩЕНИЙ чата вложения не меняются (только при отправке).
- Монеты/серия/покупки/friend-бонус: документ `eco/{uid}` (coins, fire, rf, pinv), только через runTransaction (fireAdd, syncFr, buy, migEco - миграция
  из users один раз). `sv()` пишет users/{uid} через `mergeFields` (SVF) без экономики. Правила: eco, counters, files (см. firestore.rules).
- Виджеты: причина поломки - простой `<View>` в layout (RemoteViews не умеет). Заменено; prep.sh падает, если `<View`/`<Space` вернутся. Виджет заметок перерисован.
- Обновление поверх старой: versionCode = минуты с 1970 (prep.sh), проверка подписи в verify.sh (предупреждение). Проверка обновлений: SITE/version.json
  + GitHub Releases (`GH='__REPO__'` подставляет workflow). Workflow публикует релиз с APK.
- Рендер: `morphHTML/mNode/mKids` (diff DOM) вместо innerHTML; R() и RM() морфят, `patch(soft)` для меню; `go()` по-прежнему заменяет main целиком
  (из-за WAAPI fill:forwards). Ключи узлов: data-key / data-mid / id. Элементы с `data-ks` не теряют inline style (кольцо прогресса).
- Главная: .prog (кастом цвета `hm.pc`), быстрые действия `hm.qc[key]` (PALX, lum() для цвета текста), равная высота .qb 68px, .tw с inset-полосой цвета.
- Профиль: PROF() (карточка .pf2), pCard() (чужая/превью .pc3, «PastCard ID»), pid из счётчика `counters/users` (assignPid), editP() с черновиком EP и
  плавающей стеклянной плашкой #sfl, шапка `header.hid` скрывается на вкладке профиля и в чате (в чате отдельный `header.chh.glass`), сет Gold.

## Часть 2 (сделана): живой огонёк + магазин украшений (всё в index.html, тесты t_main.js - 87 проверок)
- Версия по-прежнему 1.1.0. Старый «бегущий огонёк» (.runner) удалён; ключ покупки остался `run`, теперь это «Живой огонёк» (цена 6), `dec.run` = включён.
- Персонаж: `crSv(h,skin,{off,mode,n})` (viewBox 48x56: тело, глазки, ножки, ручки; CSS-анимации класса `.cre`, `.cr-*` в блоке /*DECOR2*/).
  Режимы `dec.cm`: sit | lift | name | hold, '' = случайно (`crMode`, кэш `RMC`, сбрасывается при смене вкладки и открытии карточки).
  lift: аватарка двигается анимацией liftA (переменная --lu), руки - CSS `d:path()` + сдвиг кисти, всё с периодом 1.6с.
  Статичный огонёк `flSv` (квадратик у монет `flm`, значок `fBadge`) скрывается, когда огонёк надет (кроме hold). Серый и с закрытыми глазами, если нет заметки сегодня.
  Формы тела по скину (`SKX[skin].sh`): flame, yin, ball, planet, donut, cat.
- Таблицы BGS/FRS/SKS/MSS/BFS/SETS/SKX: формат описан комментарием перед BGS. Цены старых предметов снижены (2-4), новые 4-12, сет 30 (скидка считается `setSum`).
  Старые сеты (THM: gold, dark, pink, rb, br, white) скрыты из магазина флагом hidden, но предметы s_* остаются у купивших. Новые сеты: id `yin, ball, planet, donut, cat`;
  части сета всегда называются `s_<id>` в bg/frame/skin/msg/bf (+ `run`), покупка через `setKeys`.
- Новая категория `bf` (рамка описания): CSS-классы `.bf.bf-<id>` (в блоке DECOR2), применяются к `.pf-bio` и `.bi` через `bfCl(dec)`.
- Графика фонов (400x560) и колец рамок (100x100) рисуется SVG-генератором `tools/gen_decor.py`: запуск `python3 tools/gen_decor.py` из корня, он сам
  перезаписывает блок `/*DECOR-START*/..` в index.html (CSS-переменные --b-* и --f-*). SMIL-анимация внутри SVG. Хочется новый фон/рамку: добавить функцию в генератор,
  запись в BGS/FRS (с 'var(--b-имя)' / ключом кольца), запустить. `tools/patch_decor.py` - одноразовый патч, повторно НЕ запускать.
- Честно пользователю: нейросетевые картинки генерировать нельзя (нет такого инструмента), поэтому «персонажи» в фонах (привидения, котики, огонёчки, пончики) нарисованы SVG.
- Заодно исправлено: «Как видят вас другие» показывало серию 0 (теперь своя серия).
- Правила Firestore не менялись (в dec лежат только id и строки).
- Не сделано/идеи: режимы огонька нельзя включать по отдельности (только один или случайно из всех четырёх); огонёк не показывается в чатах/списках (только профиль и карточка).

## Как проверять
`cd tests && NODE_PATH=/opt/npm-tools/node_modules PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node t_main.js` (Chromium есть в /opt/pw-browsers).
Синтаксис JS: вытащить `<script type="module">` в .mjs и `node --check`. Правки index.html удобно делать python-скриптом с assert на число вхождений
(строки в файле очень длинные). Java/Android-часть здесь не проверить: внимательно читать код.

## Ловушки
- RemoteViews: только TextView/ImageView/LinearLayout/FrameLayout/ProgressBar/ListView и т.п.; никакого `<View>`.
- Firestore не принимает `undefined` в данных. Документ users/{uid} < 1 МБ (поэтому файлы вынесены в `files`).
- После правок правил Firestore пользователь должен нажать Publish (напоминать!). Также выложить сайт (version.json).
- Не писать в ответах про «память»/заметки; пользователь просил именно файл-записку в проекте.
- Не создавать новые версии/репозиторий: `debug.keystore` в корне - фиксированный ключ подписи (SHA-256 10:FA:54:3F...).

## Вопросы пользователя, на которые уже отвечено
- «Только я могу менять монеты и читать переписки?» Нет, так: владелец Firebase-проекта (он) видит и меняет всё в консоли, включая переписки
  (они не шифруются); обычный пользователь может изменить только СВОИ данные (в т.ч. свои монеты - защиты от накрутки нет без Cloud Functions/Blaze)
  и читает только свои чаты. Базу присылать не нужно: монеты теперь в eco/{uid}; старые поля копируются автоматически.
