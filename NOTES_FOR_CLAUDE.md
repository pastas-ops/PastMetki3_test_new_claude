## Версия 1.1.1, часть 3 (ГОТОВО, «конечная часть»; тесты: t_main.js 88 + t_111.js + t_112.js 33 + t_113.js 34, все проходят)
Вопрос пользователя «новый вид заметок (кружки + время дата) везде, где можно писать/редактировать заметки?» - теперь ответ: ДА, везде. Места, где пишутся/правятся заметки: (1) новая заметка NEWF, (2) окно «Редактировать заметку» ed() (вкладка заметок), (3) «Редактировать» сообщение-заметку в чате emD(), (4) поле ввода в чате/группе CMP(). Во всех - одинаковый вид.
- Общие кусочки: `NFP(m,тип,знач,подпись,j)` (кружок-метка с input, для re-render через R()), `NFE(класс,id,тип,знач,подпись,data-m)` (то же для окон-диалогов, где нет R()), `NFC(д,в,x,j)` (подпись выбранных даты/времени с крестиком сброса).
- **ed()/emD()**: оба строятся одной `edHTML(o)`: у названия кружки ✓(`data-a=eprow` добавить пункт) / дата `#ed` / время `#edt` (у сообщения `#edt2`) / + (`edatt` открывает панель файлов), подпись `#edc`, пункты `.epr` = textarea `.epi` (`data-m=epi`) + кружки `.epd`/`.ept` (+ скрытый `.ept`, если время выключено в настройках) + подпись `.epc`. Диалог не перерисовывается через R(), поэтому подписи и подсветку кружков обновляет `edUpd()` (вызывается из input-слушателя для data-m edd/edtm/epd/ept и после сброса). `edAdd(строка|null,текст)` добавляет пункт. `readRows()` читает `.epi/.ept/.epd` (ept/epd с запасом на null).
  Файлы: `ATE(список,группа,open)` (вместо старого ATZ и действия `atp`): внутри диалога редактирования нельзя открывать второй диалог (openD заменяет #dlg и потеряет введённое), поэтому панель файлов раскрывается прямо в окне (`EDA.open`), `refreshAt('ed')` перерисовывает только `.atz[data-atz=ed]`. **У сообщений чата теперь тоже можно менять вложения**: `EDA={id,list,rm,msg:1,open}`; emsv пишет `at` (через attWrite, участники = SHF().members) и удаляет убранные файлы; esv проверяет `!EDA.msg`. `fx` (Отмена) обнуляет EDA.
  Клавиатура в диалоге: `kbEd(e)` (перед обработчиком keydown, после kbNew): Enter в названии -> первый пункт; Enter в пункте -> делит пункт по курсору; Shift/Ctrl/Alt+Enter -> новая строка; Backspace в начале -> склейка с предыдущим; стрелки между ячейками; Ctrl+S -> «Сохранить» (`code===KeyS`, любая раскладка). Вставка нескольких строк в пункт = несколько пунктов (отдельный paste-слушатель по классу `.epi`). Собственной истории Ctrl+Z в диалоге нет (работает родная отмена текста).
- **CMP() (поле ввода в чате)**: под полем названия строка кружков `.tbr .nfi`: ✓ `cplus` (новый пункт), дата `cdt` (min=сегодня), время `cdtm`, + `atmod` с `data-g=cmp`. Старые 📅 ⏰ 📎, `#dcap` и `catt` удалены (`capT()` остался в коде без использования). Подпись `NFC(...,'cdc')` (действие `cdc` сбрасывает дату и время), миниатюры вложений под ней. Пункты чата - textarea `data-m=ci` + кружки `cidd`/`cit` + подпись (`cidc`). Изменение даты/времени вызывает R(). Enter в пункте = следующий пункт (как раньше), **Shift/Alt+Enter = новая строка** (в kbNew), Ctrl+Enter = отправить, вставка нескольких строк = несколько пунктов, `ct` остаётся однострочным.
- **Окно файлов atMod(g)** теперь работает для трёх групп: `dr` (новая заметка), `cmp` (чат), через переменную `ATG` (текущая группа; Ctrl+V/перетаскивание/ссылки используют `ATG`). Действие `atmod` берёт группу из `data-g` (по умолчанию `dr`). Группа `ed` в окне файлов не используется (см. выше про ATE).
- Ловушки: в тестах клик по пункту меню сообщения нужно делать через ≥900 мс после правого клика/зажатия (глобальная защита `Date.now()-lpf<800` в click-обработчике). Сообщение открывается правым кликом по `[data-lt=m][data-lp=<id>]`, потом кнопка `[data-a=med]`.
- CSS части 3 - блок «1.1.1 ч.3» перед `/*DECOR-START*/`.
- Что осталось (не обязательно): у названия сообщения в чате (`ct`) нет Shift+Enter (однострочное поле); в диалоге редактирования нет своей истории Ctrl+Z; сам APK здесь собрать нельзя (собирает GitHub).

ВСЕГДА с `TZ=Europe/Moscow`. `cd tests && node t_111.js`, `node t_112.js`, `node t_113.js` (1.1.1) и `node t_main.js` (1.1.0 + заметки), с теми же переменными окружения; mock-fs.js уже знает serverTimestamp/getDocFromServer (`window.__SKEW` двигает «часы сервера»). `NODE_PATH=/opt/npm-tools/node_modules PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node t_main.js` (Chromium есть в /opt/pw-browsers).

## Ловушки
- RemoteViews: только TextView/ImageView/LinearLayout/FrameLayout/ProgressBar/ListView и т.п.; никакого `<View>`.
- Firestore не принимает `undefined` в данных. Документ users/{uid} < 1 МБ (поэтому файлы вынесены в `files`).
- После правок правил Firestore пользователь должен нажать Publish (напоминать!). Также выложить сайт (version.json).
- Не писать в ответах про «память»/заметки; пользователь просил именно файл-записку в проекте.
- Не создавать новые версии/репозиторий: `debug.keystore` в корне - фиксированный ключ подписи (SHA-256 10:FA:54:3F...).

## Вопросы пользователя, на которые уже отвечено
- «Только я могу менять монеты и читать переписки?» Нет, так: владелец Firebase-проекта (он) видит и меняет всё в консоли, включая переписки
  (они не шифруются); обычный пользователь может изменить только СВОИ данные (в т.ч. свои монеты - защиты от накрутки нет без Cloud Functions/Blaze)
  и читает только свои чаты. Базу присылать не нужно: монеты теперь в eco/{uid}; старые поля копируются автоматически.
